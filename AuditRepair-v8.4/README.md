# AuditRepair v8.4 — Controlled CPU extensions (E5, E6, E8) and E7 annotation preflight

**Release type:** experimental addendum to the verified **AuditRepair v8.3** repository. This is a new computational study, **not** a new independent annotation panel.

## Experimental status

- **E5, cached real panels:** complete on seven original annotation pools, 3 generators × 2 score sources, 20 **existing** preprocessing seeds × 10 paired PAC repetitions. A/B reproduce the archived same-audit baseline and fixed-score repair; C recomputes uncertainty for repaired labels using the same already-audited model. Only accepted states incur additional PAC computation. See `results/E5`.
- **E6, controlled synthetic useful-repair conversion:** 54 prespecified cells, 100 new synthetic preprocessing seeds per cell, 5 nested PAC repetitions per seed, 3 gold-blind group-ranking policies, fixed total audits 400. See `results/E6_full`. Synthetic *gold* is generated by the simulator but is not used for candidate formation or ranking.
- **E8, independent small-domain arithmetic reference:** scalar exact rational and high-precision Decimal checks; these are **bounded checks**, not a substitute for a general proof or a separate replication of the source PAC Labels repository.
- **E7, independent new four-model annotations:** **not run** here. Gold-blind tasks and collector/quality-gate scripts are prepared for a separate pinned-GPU run. No new LLM outputs are included.

Check the actual block manifests before claiming a block completed; E6 status is recorded per-checkpoint and in `e6_manifest.json`.

## Exact scientific contrast

For a common set of already purchased preprocessing audits A and a common sequence of PAC calibration draws D, compare:

- **A** = final same-audit DS predictions and baseline scores;
- **B** = certified repaired predictions with identical baseline scores;
- **C** = certified repaired predictions and the **same previously trained model** recomputed on the repaired labels.

The score source is either `S0 = 1 - p_DS(label | observed source votes)` or `S1 = 1 - q_text(label | text)`; the model is frozen before the PAC draws, and no new gold is used to score C. Savings are `A_cost - B_cost`, `B_cost - C_cost`, and `A_cost - C_cost`. A negative number is an *increase* in expert purchases. The full score vectors for A, B, and C are not shared as independent statistical replications.

The primary E5 example is **G1/S1 on the AG News holdout**. This holdout has been seen in previous work, so the E5 computation is a *retrospective computational extension* and is not a blind confirmatory validation.

```bash

python -m pip install -r /mnt/c/AuditRepair-v8.3/requirements.txt
cd /mnt/c/AuditRepair-v8.4
export V83_REFERENCE=/mnt/c/AuditRepair-v8.3
```

**Fast integrity checks and reference arithmetic tests:**

```bash
python code/verify_release.py
python tests/test_fast_pac.py
python tests/test_e6_design.py
python code/e8_numerical_audit.py
```

**E5 from cached annotations, explicitly reproducing a new copy:**

Recompute checkpoints have one file per `cell_id × seed` and the runner can resume under the exact same frozen protocol. Do not mix different protocol hashes.

## E7 new annotation panel — GPU required, not performed here

The `E7_tasks` folder contains eight frozen, gold-blind worklists: Qwen, Llama, Mistral and Phi for 5,000 AG News development and 2,600 holdout items (30,400 source-item requests). Each model receives half direct and half reasoning prompts, balanced across models and items. Gold and previous model predictions are removed **before** tasks are written.

**The operator must verify the actual model revision loaded by vLLM.** The `/v1/models` endpoint verifies only the served model ID, not the commit SHA. Start one pinned model at a time on the GPU and collect the two files for that family:

```bash
# Example with the Qwen model at http://127.0.0.1:8000/v1
python code/e7_collect_one_model.py --tasks E7_tasks/ag_news_5000_qwen_tasks.jsonl \
    --output e7_responses/ag_news_5000_qwen_responses.jsonl --base-url http://127.0.0.1:8000/v1
python code/e7_collect_one_model.py --tasks E7_tasks/ag_news_holdout_qwen_tasks.jsonl \
    --output e7_responses/ag_news_holdout_qwen_responses.jsonl --base-url http://127.0.0.1:8000/v1
```

Repeat with the other three pinned families and their own served-model IDs. Quality/format gating is computed **before** gold is loaded:

```bash
python code/e7_validate_and_join.py --tasks E7_tasks --responses e7_responses \
    --reference "$V83_REFERENCE" --out rerun/E7_quality_and_panels
```

The program refuses a joined panel if any family on either pool has >5% unusable/failed outputs or incomplete responses. The same dataset and already-viewed holdout do **not** make this a wholly independent confirmation of previous outcomes. Never call E7 complete until the new model responses and a fresh downstream re-analysis exist.

## Reproducibility boundaries

1. A v8.3 result remains frozen; v8.4 is an explicit *new* protocol, not a retroactive replacement of its original v8.3 results. See `protocol/frozen_e5_as_executed.json` and `protocol/frozen_v84.json`.
2. E5 uses **existing seeds** and fixed panels; its seed bootstrap describes conditional algorithmic variability. It does not generalize to new annotators.
3. E6 draws new simulated populations at **100 independent seeds per design cell**; five PAC repetitions are nested within each seed and three policies share each population. No claims are made beyond the specified simulator.
4. E8 reference calculations check finite cases and numerical parity; they are not a proof that every floating-point path obeys the ideal mathematical guarantee.
5. No additional model annotations, production costs, or deployment measurements have been fabricated. All E7 model-specific outputs are pending.

AUDIT REPAIR v8.2 — TARGETED EXPERIMENTAL AMENDMENT
4 November 2026

This directory holds the targeted v8.2 amendment to the frozen v8.1 study:
the corrected acceptance replay, the active-repair analyses and the matched
power comparison. All three computations are complete.

WHAT IS NEW

1. The corrected implementation makes strict remainder acceptance with exact
   integer numerators and a conservative represented-grid guard. Eight focused
   tests include the zero-margin counterexample.
2. The actual conventions are fully specified: terminal final PAC rejection,
   sticky group-CS rejection, exact bets/caps/boundaries, and the current
   uniform-warm-up factorial algorithm. A ninth regression distinguishes the
   two PAC conventions.
3. The 42-cell result is separated into 32 inactive, 7 active/all-zero and 3
   active/nonzero cells. All 31 accepted states have positive gain over final
   same-audit DS. Their 620 score/calibration comparisons include 557 unchanged
   costs, 33 savings and 30 increases. Complete mechanisms and tails are supplied.
4. Reporting tables remove the practical-exclusion flags and distinguish
   savings divided by pool size from savings divided by mean baseline cost.
5. A frozen new comparison runs 30 fixed populations with 1,000 common audit
   orders at group alpha 0.05 and 0.005. It measures isolated group tests with
   full allowance, not whole-shortlist power.

RUN ON WSL

From this directory, inside a Python 3.12 environment with the pinned
requirements installed:

  bash run_revision.sh

The default verifies the completed release and runs nine focused regression
tests. It does not start a fresh full factorial or regenerate annotations.
The launcher selects an explicit V82_PYTHON, active venv, project .venv, python3,
or python, in that order. The earlier missing-python alias is not required.
run_all.sh is a compatibility wrapper for this same revision launcher.

To repeat only the bounded revision computations into a NEW directory:

  bash run_revision.sh --recompute results_local_reproduction

Existing destinations and paths inside protected release folders are rejected.
The command records that runtime and repeats the acceptance replay, accepted
state reconstruction and matched power study. Outputs are a reproduction of
the same seeds, not a new statistical sample. Expected CPU work is a few
minutes; it uses no LLM calls or GPU. V82_WORKERS defaults to 2.

Use the existing working environment first. requirements-experiments.lock is
the complete observed 18-package dependency closure for the CPU experiments and
plots, with versions pinned. provenance/dependency_lock.json records platform,
Python and installed distribution metadata hashes. This is not a wheel-hash
lock and does not invent a full historical WSL dependency snapshot.

SCOPE

The results refine a conditional diagnostic claim. They do not justify general
ineffectiveness of cleaning, practical equivalence, or new-panel claims. Exact
rational checks, archived execution replay and the prior second-machine
reproduction are distinct types of evidence; none is a new annotation sample.
